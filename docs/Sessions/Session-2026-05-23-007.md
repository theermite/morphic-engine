## Travail effectué

### 1. Rust crate `@morphic/wasm-core`

**Cargo.toml + lib.rs** : NaCl box via `crypto_box@0.9.1` (RustCrypto, pure Rust, byte-compatible avec tweetnacl). 5 exports wasm-bindgen :
- `wasmGenerateKeypair()` → `WasmKeyPair { publicKey, secretKey }`
- `wasmRandomBytes(len)` → `Uint8Array`
- `wasmGenerateNonce()` → `Uint8Array` (24 bytes)
- `wasmEncryptBox(plaintext, recipientPk, senderSk, nonce)` → `Uint8Array`
- `wasmDecryptBox(ciphertext, nonce, senderPk, recipientSk)` → `Uint8Array` (ou `Err(JsError)`)

**Constants centralisés** : `KEY_LENGTH = 32`, `NONCE_LENGTH = 24`. Helper `validate_box_inputs()` factorise les vérifications de longueur (PET §5 defensive assertions ≥2 par fonction critique).

**Build pipeline** : `wasm-pack@0.13.1` cible `web` + `bundler`. Output `pkg/` ~58 KB ESM + .wasm + .d.ts. Disabled `wasm-opt` (version bundled trop ancienne pour bulk-memory ops rustc 1.82+, browsers modernes supportent natif).

**Veille marker** : `[VEILLE] wasm-pack@0.13.1 verifie 2026-05-23 via local install`.

### 2. Tests Rust (Anti-Circular Layer 1 — formal properties + fault injection)

`tests/proptest_roundtrip.rs` :
- **4 proptest! properties × 1024 cases = 4096 crypto roundtrips** :
  - `prop_box_roundtrip_identity` — `decrypt(encrypt(m)) == m`
  - `prop_box_tamper_detection` — bit-flip aléatoire → Poly1305 catch
  - `prop_box_wrong_nonce_fails` — nonce différent → auth failure
  - `prop_box_wrong_key_fails` — clé secrète différente → auth failure (+ sanity positive)
- **5 fixtures déterministes** :
  - `key_length_is_32`, `nonce_length_is_24`, `ciphertext_has_poly1305_tag_overhead` (16 bytes), `empty_plaintext_roundtrip`, `truncated_ciphertext_fails`

**Résultat** : `cargo test --release` → 9/9 ok en 12.26s.

### 3. TS bridge `packages/engine/src/wasm-bridge.ts`

Loader asynchrone + orchestrateur fallback :
- `CryptoBackend` interface (kind: 'wasm' | 'js' + 4 méthodes)
- `getJsBackend()` : wrap synchrone tweetnacl (always available)
- `loadWasmBackend()` : dynamic import `@morphic/wasm-core` + init + smoke check 24-byte nonce
- `getCryptoBackend()` : mémoïsé, tente WASM, fallback `jsBackend` sur n'importe quelle erreur
- `__setBackendForTesting()` : injection test-only
- `makeWasmBackend(mod)` : factory, fait `new Uint8Array(mod.xxx(...))` sur chaque sortie (defensive copies pour découpler de la mémoire wasm-bindgen)

**Veille marker** : `[VEILLE] @morphic/wasm-core@workspace:* verifie 2026-05-23 via local workspace`.

## Difficultés rencontrées + résolutions

| Problème | Résolution |
|----------|------------|
| wasm-opt bulk-memory validation errors | `wasm-opt = false` dans Cargo.toml `[package.metadata.wasm-pack.profile.release]` |
| Warning `KeyInit` unused | Retiré de `use crypto_box::aead::{...}` |
| `proptest_config` placement error | `#![proptest_config(...)]` doit être FIRST dans le bloc `proptest!` (pas après un doc-comment) |
| Veille hook Layer B bloque `[SKB]`/`[VEILLE-SKIP]` sur dependency manifests | Émission de vrais `[VEILLE]` markers (wasm-pack et @morphic/wasm-core) |
| `vi.doMock` + `tweetnacl instanceof Uint8Array` strict | Remplacé tests cross-backend par `__setBackendForTesting` injection (pattern plus robuste, plus rapide) |
| jsdom `TextEncoder` realm mismatch jsdom vs node | `Uint8Array.from([0x68, ...])` au lieu de `TextEncoder` (pattern déjà présent dans `e2e-crypto.test.ts`) |
| Coverage gap sur `makeWasmBackend` internals (lines 101-121 = 83.87%) | Nouveau test "returns a backend that wraps the wasm module methods" avec mock synthétique exerçant chaque méthode + assertions defensive-copies → 100% lines |
