### Couches défense (Critical 95%)

- **Dignity §a BLOCKING guard** : `canCollectIdentity()` retourne `true` IFF `started && completed`. MC/DC 4 lignes (T1 F&F→false, T2 T&F→false, T3 T&T→true, T4 F&T impossible state-machine-wise).
- **Validation-before-mutation** : `isValidStep` (closed enum poka-yoke) + typeof check pour `value` AVANT toute lecture/mutation d'état. `existing.started`, `existing.completed`, `existing.currentStep` checks AVANT advance.
- **Defensive assertions** (8) : TypeError sur step non-enum, TypeError sur value non-string (completeStep), Error "not started" sur completeStep/skipStep avant startOnboarding, Error "invalid order — already completed" sur post-completion, Error "invalid order — expected X got Y" sur out-of-order, snapshot-stable state on failure (state NOT mutated).
- **Idempotence** : `startOnboarding` 2× = no-op (preserve progress). State machine ne reset jamais accidentellement.
- **Order enforcement** : `completeStep('density')` alors que currentStep='motion' → throws. Pas de bypass possible.
- **SSR-safe** : 4 guards (`document`, `CustomEvent`, `localStorage`, types primitifs en read).
- **Storage corruption-tolerant** : `isPlainObject` + try/catch sur `getItem`/`setItem`/`JSON.parse` + `isValidStep` filter sur `completedSteps[]` à la rehydration. Malformed JSON, non-object, out-of-shape sub-key → fallback idle.
- **Rehydration** : `getOnboardingState()` après `__reset` lit storage et reconstruit l'état (current step dérivé de `completedSteps.length`).
- **PBT** (3) : closed enum step (fast-check rejette tout autre input), complete sequence atteint toujours `completed` (terminating property), skipStep idempotent sur identical defaults.
- **MC/DC** (4 rows) sur guard `started && completed` : voir tableau ci-dessus.
