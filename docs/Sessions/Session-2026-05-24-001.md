## Travail realise

### B-021e — Engine alignment 4 axes sensoriels (morphic-engine)

**Probleme** : post-deploy v3, Jay rapporte 4 axes sensoriels visuellement inertes (motion, contrast, density, fontSize). Cause racine : ces axes ecrivaient uniquement la CSS var `--morphic-X` mais pas l'attribut DOM `data-morphic-X`. Les selecteurs CSS du Lab `[data-morphic-X=value]` ne matchaient donc jamais. Le pattern `setAttribute` etait deja present dans theme.ts et font-family.ts mais manquait dans les 4 autres.

**Fix** :
- `src/motion.ts`, `src/contrast.ts`, `src/density.ts`, `src/typography.ts` : ajout `setAttribute('data-morphic-X', resolved)` a cote du `setProperty` existant
- `src/init.ts` : ajout bloc bootstrap density manquant (regression silencieuse B-009) — `isValidDensity()` + CSS var + data attr
- +14 tests Beyonce Rule (verrouillage du comportement setAttribute sur les 4 axes)
- Bump version 2.0.0-beta.0 -> 2.0.0-beta.1, publie Verdaccio npm.shinkofa.com

## Decisions

- Pattern architectural confirme : chaque axe engine DOIT ecrire `setProperty` (CSS var) + `setAttribute` (data attr). Le CSS ne peut pas cibler les custom properties via `[attr=val]`.
- Polling interval : 1s pour Pomodoro (granularite seconde), 500ms pour CommandPalette (feedback ouverture rapide).
- Pas de `requestAnimationFrame` ni `subscribe` — engine n'expose pas d'observable (decision B-001).
