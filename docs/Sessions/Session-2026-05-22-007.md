**Architecture clés** :
- `safeResolve` wrap resolver dans try/catch → throws comptés en `unresolved` (jamais propagé)
- Idempotence : `cleanInjected` + `restoreReplaced` AVANT chaque render
- Replace mode stocke originalText dans attribut data-* → restauré on disable
- Replace mode no-op si aucune résolution (préserve texte plutôt que vider)
- SSR : persist intent, return `{ mode, rendered: 0, unresolved: 0 }`

## Décisions / Deviations

| Décision | Raison |
|----------|--------|
| Attribut `adapt-symbol` (W3C spec) au lieu de `data-symbol` (CDC) | Spec W3C est la source de vérité technique. Divergence documentée dans PET. |
| 3 modes only (`before`/`after`/`replace`), pas de tooltip | Tooltip = UI complexité (hover state, positionnement). Hors scope core engine. Différable en B-104b si demandé. |
| Pattern resolver (host fournit URLs) | Évite bundling lourd (5000+ pictogrammes), flexibilité licensing par projet (commercial vs non-commercial). |
| `safeResolve` catch throws → unresolved | Resolver tiers peut throw ; ne doit pas casser le rendu global. Counted, pas masqué. |
| `replace` no-op sans résolution | Vider un élément sans pictogramme = perte d'info. Mieux préserver texte. |
