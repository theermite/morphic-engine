02Ce que ce n'est pas

Pas un overlay.
Pas un patch.
Un système nerveux.

Les overlays d'accessibilité

Un script tiers, un widget en bas à droite, une promesse de conformité instantanée. Le contrôle reste chez le vendeur. Les données sont collectées. La FTC a sanctionné l'un d'eux en 2024 — un million de dollars, 1 023 sites concernés.

Le module morphique Shinkofa

Un moteur intégré au cœur du produit. Code ouvert, auditable. Préférences chiffrées de bout en bout. Le contrôle reste chez l'utilisateur. Détachable en deux clics, données exportables.

L'adaptation n'est pas une option d'accessibilité posée par-dessus. C'est la matière du produit.

03Ce qu'il fait

Treize axes.
Trois minutes.
Une seule personne :
vous.

Si vous préférez peu de mouvement, l'interface ralentit. Si vous lisez mieux avec une typo dense, elle se densifie. Si votre énergie est basse aujourd'hui, l'interface se calme : moins d'animations, moins de sollicitations, plus d'espace.

Pas parce que vous avez coché une case dans un menu. Parce que le système comprend — et parce que vous gardez le dernier mot, à tout moment.

06Ce qu'on refuse

Quatre lignes
qu'on ne franchira pas.

  • Aucune donnée d'adaptation ne quitte l'appareil en clair. Le serveur ne voit que des deltas chiffrés. Il n'a même pas la clé.
  • Aucun dark pattern, à aucun moment du flow. Ni à l'accueil, ni à la limite, ni au départ. Désinscription en deux clics, export proposé avant.
  • Aucun tracking tiers, aucun analytics intrusif. La télémétrie est agrégée, anonyme, opt-in, désactivable d'un clic.
  • Aucun storytelling fabriqué. Si on vous parle d'une fonctionnalité, c'est qu'elle existe et qu'on peut vous montrer son code.

07Ce qu'on construit

Vingt-neuf briques.
Six phases.
Aucune brûlée.

La méthodologie est brick by brick — une brique, une preuve, un commit. Pas de « on finira plus tard ». Pas de « ça suffira pour démarrer ».

Phase 1Fondations

Le squelette. Architecture en trois couches. Les tests d'abord, le code après. Le compilateur strict comme première garde.

Phase 2Sensoriel

Cinq axes sensoriels gradués — thème, mouvement, densité, taille de texte, contraste. Le confort avant l'identité.

Phase 3Cognitif & accueil

Mode focus, réduction des distractions, prédictibilité. Et l'onboarding en trois décisions — pas une de plus.

Phase 4Mémoire

Persistance locale d'abord, synchronisation entre appareils ensuite — toujours en zéro-knowledge, jamais imposée.

Phase 5Résilience

Isolation des couches lourdes hors du thread principal. L'interface ne ralentit jamais, même quand l'arrière-plan travaille fort.

Phase 6Dévoilement

Démonstration sur theermite.com, interopérabilité avec les standards d'accessibilité existants, RGPD intégré, publication publique.

Détail technique pour qui veut auditer

Architecture en cinq couches

  • Visible — TypeScript 5.7 strict + Web Components v1 + Lit 3.2. Framework-agnostic. Adapters React/Vue/Svelte/Astro en couches minces.
  • Validation critique — Rust 1.87 compilé en WebAssembly. Tokens W3C DTCG dérivés via Style Dictionary 5.4.
  • Résilience — Effect-TS 3.10. Retry exponentiel, circuit breaker. Un échec de synchronisation ne dégrade jamais l'expérience locale.
  • Isolation — Web Workers. Yjs CRDT lazy-loaded (50 Ko), chiffrement NaCl box, dérivation tokens. Le thread principal reste sous 50 ms d'INP.
  • Relais optionnel — Phoenix 1.8 sur Elixir 1.19, serveur Bandit 1.11. Channel zero-knowledge — le serveur relaie sans déchiffrer.
