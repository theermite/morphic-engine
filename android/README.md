# morphic-android (適応)

Native Android port of the **Morphic Adaptation Module** — a framework-agnostic,
drop-in engine that adapts a UI to the user's sensory preferences (theme, motion,
density, contrast, font size) and enforces a **sensoriel-before-identity**
onboarding (the user's comfort is honored before any identity is collected).

Pure-Kotlin logic + thin Jetpack Compose surface. The module **exposes** the
resolved choices; the host app decides how to render them (parity with the
headless web API). Intention: `../docs/CDC.md` §4.4. Execution journal:
`../docs/PET-Android.md`.

This is a **separate Gradle build**, isolated from the repo's pnpm/TypeScript
workspace. The two coexist in one repo but never share a build.

## Quick start

### 1. Wrap your UI in the provider

```kotlin
import com.theermite.morphic.state.MorphicState
import com.theermite.morphic.theme.MorphicProvider
import com.theermite.morphic.theme.LocalMorphic

val morphicState = remember { MorphicState() }

MorphicProvider(state = morphicState) {
    // Material 3 light/dark is orchestrated from the user's resolved theme.
    val resolved = LocalMorphic.current
    // Apply font size / density / contrast from `resolved` (the host owns the numbers).
    MyApp()
}
```

### 2. Run the dignified onboarding first

```kotlin
import com.theermite.morphic.onboarding.*

val onboarding = remember { MorphicOnboarding(morphicState) }

MorphicOnboardingScreen(
    onboarding = onboarding,
    steps = listOf(
        OnboardingStepUi(
            step = OnboardingStep.THEME,
            title = "How do you prefer to read?",
            choices = listOf(
                OnboardingChoice("auto", "Match my system"),
                OnboardingChoice("light", "Light"),
                OnboardingChoice("dark", "Dark"),
            ),
            skipLabel = "Decide later",
        ),
        // … MOTION and DENSITY steps (host-supplied copy / i18n) …
    ),
    onComplete = {
        // canCollectIdentity() is now true — only here may identity UI appear.
    },
)
```

The `canCollectIdentity()` guard returns `true` **only** once the three sensoriel
steps are done. Gate any identity-collection screen behind it.

## Accessibility

The onboarding screen ships accessible by construction: each step title is a
TalkBack heading, every control has a `contentDescription`, and touch targets are
≥ 48 dp. Verify with TalkBack + Accessibility Scanner in the `sample/` app.

## Build & test

```bash
cd android
gradle wrapper --gradle-version 9.1.0   # first time only — generates the wrapper jar
./gradlew :morphic:testDebugUnitTest     # unit tests (pure logic)
./gradlew :morphic:koverHtmlReport       # coverage report (build/reports/kover/html)
./gradlew :sample:assembleDebug          # build the demo app
```

Opening `android/` in Android Studio generates the Gradle wrapper jar automatically.

## Where it gets proven

- **CI** (`.github/workflows/android.yml`) builds, lints, tests, reports coverage,
  runs the publish dry-run and builds the sample on every push touching `android/**`.
- **Local machine** (with the Android SDK) drops the library into a real app for
  human validation. The VPS that authors this code has no Android toolchain by design.

Coverage of the Critical onboarding logic is 100% (Kover). Composables are not
coverage-floored (generated bytecode is unmeasurable) and are validated in `sample/`.
